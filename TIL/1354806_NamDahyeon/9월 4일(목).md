1. FE 성능 측정 도구
- 개발자도구 - Network
- 개발자도구 - Performance
    - LCP(Largest Contentful Paint)
        - 화면에 처음 이동했을 때부터, 가장 큰 핵심 콘텐츠가 화면에 보이기까지 걸린 시간
    - CLS(Cumulative Layout Shift)
        - 페이지 로딩 중에 요소들이 갑자기 움직이는 정도
            = 시각적 안정성
- 개발자도구 - Lighthoust
    - 웹 페이지 품질 측정 자동화 도구
        -> Performance 탭 상위 호환
    - 웹 사이트의 성능·접근성·SEO 등을 자동으로 점수화

2. 서버와 클라이언트 렌더링 비중 설계
- 서버와 클라이언트 렌더링 비중을 설계한다라는 개념 자체를 처음 접했다,,

- 클라이언트 렌더링(React)
    - 빈 index.html과 JS 번들을 서버에서 클라이언트로 보내줌
    - 그러면 클라이언트는 API 호출 및 재렌더링, DOM 생성 및 조립 등을 수행해야

- 서버 사이드 렌더링
    - 완성된 HTML과 JS 번들을 서버에서 클라이언트로 보내줌
    - 클라이언트는 갖다 쓰면 됨

- 초기 HTML을 서버에서 미리 만들어서 보내주는 영역이 늘어난다는 것
    -> 클라이언트 JS 감축
        -> 초기 LCP 유리

- SSR, RSC
    - 상태/이벤트 불가(useState, useEffect, onClick)
    - 브라우저 전용 API 불가(window, document)
    - 인터렉션 부족

3. PNG vs. SVG
    - PNG
        - 픽셀 기반 무손실 압축 이미지
            - 투명 배경 UI 요소에 적합
            - 비교적 용량이 큼 -> 확대 시 깨짐
    - SVG
        - XML 코드 기반 이미지
            - 비교적 용량이 작음 -> 확대해도 깨지지 x
            - 복잡한 이미지에선 용량 ↑
